# Support

## Usage and setup questions

Before opening an issue:

1. Read the [README](README.md).
2. Check the [configuration reference](docs/configuration.md).
3. Review [operations and deployment guidance](docs/operations.md).
4. Search existing issues for the same symptom.

If the problem is reproducible incorrect behavior, use the **Bug report** issue template.

If you are proposing a new product capability, use the **Feature proposal** template.

## Contributor questions

For questions about an existing contributor task, comment on that issue so the discussion remains attached to the work.

For Drips Wave issues, use the Wave application flow for contributor selection rather than requesting assignment outside the Program.

## Security issues

Do not open a public issue for vulnerabilities or secret-exposure problems.

Follow [SECURITY.md](SECURITY.md) for private reporting guidance.

## What to include in a bug report

Include:

- SoroSLO version or commit;
- operating system/runtime details when relevant;
- the smallest safe configuration that reproduces the problem;
- expected and observed behavior;
- relevant run IDs or redacted logs;
- exact verification commands already attempted.

Never include private keys, mnemonic phrases, webhook secrets, private RPC credentials, bearer tokens, or credential-bearing URLs.
